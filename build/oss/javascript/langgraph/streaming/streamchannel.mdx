---
title: StreamChannel
description: Use StreamChannel as the stream transformer projection primitive.
---

`StreamChannel` is the projection primitive for custom streaming data. It always exposes an iterable stream on `run.extensions.<name>`. The constructor argument decides whether each push also flows into the run's main event stream as a `custom:<name>` event—that is, whether the projection's values show up when iterating raw protocol events.

```ts
const sideChannel = new StreamChannel<T>();
const partOfMainStream = new StreamChannel<T>("timeline");
```



## Decision Rule

Use one `StreamChannel` whenever you need a streaming projection. The only decision is whether each push should also flow into the main event stream as a `custom:<name>` event.

| Need | Use |
| ---- | --- |
| Side-channel projection only | `new StreamChannel<T>()` |
| Also flow each push into the main event stream | `new StreamChannel<T>(name)` |




Named channel payloads must be serializable, because each pushed value also becomes a `custom:<name>` protocol event in the main stream. Keep promises, async iterables, class instances, and other in-process handles in unnamed channels.

## Unnamed channels

Unnamed channels are available only as a side-channel projection through `run.extensions`. Pushed values do not appear in the run's main event stream.

```ts
import { StreamChannel } from "@langchain/langgraph";

const progressTransformer = () => {
  const progress = new StreamChannel<{ step: string }>();

  return {
    init: () => ({ progress }),
    process(event) {
      progress.push({ step: event.method });
      return true;
    },
  };
};
```




## Named channels

Named channels are available through `run.extensions`, and the stream handler also forwards each `push()` into the run's main event stream as a `custom:<name>` protocol event. Any consumer iterating raw events on the run sees those pushes alongside the built-in channels (`messages`, `values`, `lifecycle`, and so on).

```ts
import { StreamChannel } from "@langchain/langgraph";

const toolActivityTransformer = () => {
  const activity = new StreamChannel<{
    name: string;
    status: "started" | "finished" | "error";
  }>("toolActivity");

  return {
    init: () => ({ toolActivity: activity }),
    process(event) {
      if (event.method === "tools") {
        const data = event.params.data as { tool_name?: string; event?: string };
        if (data.tool_name && data.event) {
          activity.push({
            name: data.tool_name,
            status: data.event === "tool-error" ? "error" : "started",
          });
        }
      }
      return true;
    },
  };
};
```




## Lifecycle

`StreamChannel` lifecycle is managed by the stream handler when the channel is returned from a transformer's `init()` method. Transformers push data, but do not close or fail the channel directly.

Both unnamed and named `StreamChannel`s are closed or failed by the stream handler.
